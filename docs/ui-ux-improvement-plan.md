# SASA 공강맵 UI/UX 개선 계획

## 현재 상태 요약

- 핵심 기능은 `교실 찾기`, `통합 검색`, `시간표`, `마이페이지/공강 등록`, `관리자`로 분리되어 있다.
- 모바일 하단 탭 구조는 방향이 좋지만, 화면별 정보 밀도와 상호작용 방식이 서로 다르다.
- 한글 문자열 인코딩이 깨져 보여 실제 사용자가 기능을 이해하기 어렵다.
- `FindRoom.jsx`, `MyPage.jsx`, `Timetable.jsx`가 많은 인라인 스타일과 화면별 중복 규칙을 갖고 있어 UI 수정 비용이 높다.

## 1단계: 신뢰 회복과 기본 사용성

목표: 사용자가 앱을 열었을 때 "깨진 앱"처럼 보이지 않게 만든다.

- 모든 깨진 한글 문구를 정상 UTF-8 문자열로 복구한다.
- `README.md`도 프로젝트 설명, 실행 방법, 배포 구조를 한국어로 정리한다.
- 공통 용어를 통일한다: `공강`, `수업 중`, `사용 중`, `점검 중`, `승인 필요`, `사용 불가`.
- 빈 상태, 로딩 상태, 에러 상태 문구를 화면별로 추가한다.
- Vite 기본 템플릿 잔여 파일인 `client/src/App.css`는 사용 여부를 확인한 뒤 삭제한다.

## 2단계: 지도 UX 개선

목표: 공강맵의 첫인상을 "지도를 보고 바로 판단하는 도구"로 만든다.

- 지도 상단에 현재 기준 시간을 고정 표시한다: `오늘 6교시 기준`.
- 상태 범례를 접을 수 있는 작은 패널로 만들고, 모바일에서 지도 영역을 가리지 않게 한다.
- 교실 선택 시 하단 시트 형태로 상세 정보를 보여준다.
- 방 상태 색상은 유지하되 채도와 대비를 정리한다.
- 확대/축소 버튼은 `+`, `-`, `초기화` 대신 아이콘 버튼과 툴팁으로 정리한다.
- 층 선택은 오른쪽 세로 버튼보다 상단 segmented control 형태를 검토한다.

## 3단계: 공강 등록 흐름 개선

목표: 마이페이지에서 "언제, 어디에 있는지"를 빠르게 등록하게 만든다.

- `현재 교시`와 `예약 등록`을 명확히 구분한다.
- 방 목록 필터를 `층`, `건물`, `상태` 순서로 정렬한다.
- 이미 등록한 위치가 있으면 같은 시간대 중복 등록 대신 수정 흐름을 보여준다.
- 등록 완료 후 친구 목록과 지도 상태가 바로 갱신되도록 한다.
- 사용자가 등록한 위치 공개 범위를 설명한다: 친구에게만 보임, 전체 지도에 표시됨 등 정책 확정 필요.

## 4단계: 검색 UX 개선

목표: 검색이 "전체 데이터 덤프"가 아니라 빠른 탐색 도구처럼 느껴지게 만든다.

- 검색 타입 순환 버튼을 segmented control로 바꾼다: `전체`, `교실`, `과목`, `교사`.
- 초기 빈 검색은 인기/최근 항목 대신 안내 상태를 보여준다.
- 결과 카드는 교실, 과목, 교사별 레이아웃을 다르게 한다.
- 상세 시간표는 긴 텍스트 리스트 대신 요일/교시 칩으로 보여준다.
- 검색 실패와 서버 오류를 구분해 표시한다.

## 5단계: 시간표 UX 개선

목표: 개인 시간표 입력을 반복 사용 가능한 편집 도구로 만든다.

- 교시/요일 상수와 색상 팔레트를 공통 module로 분리한다.
- 과목 추가 모달에서 추천 수업과 직접 입력을 탭으로 분리한다.
- 모바일에서는 표 전체를 축소하기보다 하루 단위 탭 보기를 제공한다.
- 저장 중, 저장 완료, 저장 실패 상태를 셀 또는 상단에 명확히 표시한다.
- 과목 색상은 현재 해시 기반을 유지하되 접근성 대비를 검사한다.

## 6단계: 디자인 시스템 정리

목표: 인라인 스타일을 줄이고 화면 간 일관성을 만든다.

- 공통 CSS 토큰을 확장한다: 색상, 간격, 그림자, border radius, 상태 색상.
- 공통 UI module을 만든다: `Button`, `IconButton`, `Badge`, `Panel`, `EmptyState`, `LoadingState`.
- 카드 안에 카드가 중첩되는 화면을 줄이고, 반복 항목만 카드로 유지한다.
- 모바일 하단 탭의 label 길이와 active 상태를 정리한다.
- hover 효과는 desktop에만 의미 있게 남기고, 모바일에서는 press 상태 위주로 조정한다.

## 7단계: 검증 계획

- `npm run check`를 UI 수정 전후로 실행한다.
- 주요 화면을 desktop 1280px, mobile 390px 기준으로 캡처해 비교한다.
- 지도 화면은 방 선택, 층 변경, 확대/축소, 패닝을 수동 확인한다.
- 인증된 사용자와 비인증 사용자 상태를 나눠 확인한다.
- 긴 과목명, 긴 교실명, 친구 이름 10명 이상 같은 데이터로 overflow를 확인한다.

## 추천 구현 순서

1. 깨진 한글 복구와 상태 문구 정리
2. 공통 API client와 공통 시간표 상수 분리
3. 지도 상세 패널과 범례 정리
4. 검색 타입 segmented control 적용
5. 마이페이지 공강 등록 흐름 개선
6. 시간표 모바일 보기 개선
7. 공통 UI module 정리
